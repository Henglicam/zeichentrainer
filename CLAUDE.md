Working language: **English.** Reply to H in English. Short, direct, no excessive politeness.

## What this is
Chinese character trainer for adults (spaced repetition), a reinterpretation of 悟空识字 without the kids' aesthetic.
User: H, product manager, Beijing, **phone-only (Android/Xiaomi, Chrome, VPN), no computer**.
UI language: English. Learning content: Chinese + pinyin + English meaning.

## Live deployment
- Repo: `henglicam/zeichentrainer` · GitHub Pages, branch `main`, folder `/ (root)`.
- URL: `https://henglicam.github.io/zeichentrainer/`
- Push to `main` → Pages rebuilds automatically (~1–2 min). `index.html` must stay in the repo root.
- The site is **public** (free plan). User data lives exclusively on the device (IndexedDB), never in the repo.

### The flow (AI-first — "nobody wants to see OCR if not necessary")
1. **Camera:** `<input type="file" capture="environment">` (Take photo) or `<input type="file" multiple>` (**From album** — several at once, all land in the inbox, the first opens in crop mode; `addPhoto` per file) → the photo is normalized (EXIF baked in, max 1600 px) and stored in `inbox`. A pulsing "Processing photo …" placeholder appears at once; the inbox re-renders on `visibilitychange`; pull-to-refresh is off (`overscroll-behavior-y: contain`).
2. **Frame:** the photo lands directly in crop mode (bright dashed frame with a dark outline, nothing dimmed, corner handles resize, dragging inside moves, preview below). **Reading starts by itself 1.2 s after the finger lifts** (`READ_TIMER`; a corner drag restarts the wait; "Read now" and a small "Image only" link remain). No dialogs in the flow: no frame → nothing happens, the same text from the same photo is an inline note ("This text is already saved from this photo.", `d.c===c&&d.shot===id`); from another photo it becomes a second card (v118). **Each reading of a photo has a run number** (`READ_RUN[id]`, v117): a corner drag during a reading starts a new one, and the older one abandons at its next step — no status text, no result, no AI call (H's diagnostics showed the same DeepSeek request twice in one second: two readings of the same frame had both finished). **The frame stays on the photo** through reading and the card preview (`cropRectStyle` re-draws it from `CROP.rect` in percentages after any re-render) and goes only on Save or Cancel; a corner drag meanwhile re-reads.
3. **Read** (`cropSign`): the framed area is **straightened first** (`deskewBlob`: projection-profile skew estimate on a ≤ 360 px copy, ±20° in 1° steps then half degrees, text pixels = far from the median brightness so both polarities count; `readPass`; **digits are kept** when fairly sure (confidence ≥ 70) and near the characters' height (0.4–1.6 × the line's median box height — the boxes' heights swing: a ribbon ring once read as a 1 at 2.1 ×, the real 30 of 30分钟 measured 0.55–0.7 ×; H: the number was missing from the translation); letters stay out; a number reads as itself in `lineMeaning` and stays one token in the pinyin, `pySpaced`) — the status text lives in `READING[id]` and is re-queried on every update, so a re-render (foreground return, AI answer for another photo) cannot swallow it or the error; the user sees **one line with a moving bar** (`readingHTML`: "Reading the text …") for every step, only failures show as text (H: the steps are of no use to the user); a step that lasts longer than `READ_STUCK` (20 s) shows its own text under the bar ("still at: loading the reader …", `READ_AT`), because a stuck step is a failure; On Done the strokes are rendered black on white at ~80 px and read by the same Tesseract model (`recognizeStrokes`: the model gives no per-symbol alternatives, so three readings are combined — single-word PSM 8 reads hand strokes far better than single-character PSM 10 — ranked by confidence, then what fits the neighbours first); the results appear as big buttons under the pad; tapping one replaces the character and closes the sheet; Clear to draw again. Nothing downloaded, offline, nothing leaves the device; a print-trained model on handwriting, so clean strokes matter — field accuracy unknown.
4. **Meaning priority** (H's rule): online AI → phrasebook → offline model → word gloss. `aiLive()` = key set + auto on + `navigator.onLine`. While the AI is live the offline model is not run and Save waits for the running AI check (`sg.aiPromise`); if the call fails, `sg.aiErr` is set and the offline model takes over; with neither, the card gets the gloss and `mt.pending:true` and is completed by the post-save auto run when online.
5. **After saving:** the note under the photo says "Card saved — 养乐多." plus "Translation pending." / "Flagged for review." when so (no sources, no AI — H, v105) (the **Next photo** button of v39–v93 is gone — H, v94; the camera tab's own button is enough). Photos picked from the album that are still waiting keep their CROP button below. `QSCARD[id]` remembers the card; if the AI answers later, the green suggestion box with **Accept / Dismiss** appears right there.

### Online AI review (T3, opt-in, text only)
- **Setup:** More → Online AI review → **provider** (`AI_PROVIDERS`: DeepSeek default — **field-verified from the phone, no VPN** —, Qwen/Alibaba Bailian, GLM/Zhipu, Claude, custom OpenAI-style base URL; the Chinese ones take WeChat Pay/Alipay, H could not buy Anthropic credit from China), API key (settings store, device only, never exported), model (defaults `deepseek-chat`, `qwen-plus`, `glm-4-flash`, `claude-sonnet-5`), checkbox "Check every new card with the AI automatically" (default on). Settings: `aiProvider`, `aiBase`, `aiKey`, `aiModel`, `aiAuto`.
- **Answers are checked (v97):** every `zh` is normalised to simplified characters (`t2s`, v103 — told that the sign is traditional, the model answered with traditional `zh`, and 養樂多 has no dictionary entry, so the meaning lost "Yakult"; a traditional `zh` becomes `zht` when the model gave none; the prompt says "always simplified"); a meaning without Latin letters (the model once echoed the Chinese text as `m`) is dropped and logged, the fields keep the reading's own gloss; the prompt says "in English only" and that the text is usually a sign, menu item, product name or brand — "when the readings circle around a well-known brand, zh is that name"; before calling a text bad it must try the `alt` readings and answer with the plausible one (v98 — on the phone it called the soup garbage, correctly, and left 养浴多 / 次乐多 / 开乐多 unused).
- **Garbage is garbage (v95):** the prompt tells the model that the OCR text may be unreadable and asks for `bad:true` then — keep `zh`, empty `m`, say so in the note, **never replace an unreadable text with a guess** (H's Yakult logo: the AI turned 习/汶… into 了 "completed action marker" and waved 夸交多 / 一汰 / 洛相本 through as checked). A bad answer changes nothing in the Read preview: red head "This reading looks wrong — frame the text tightly and read again, or fix the characters.", the fields keep the reading's own pinyin and gloss, the review flag is pre-ticked with the note "the reading looks wrong", Save stores `mt.suspect` ("the text looks misread") and unverified; after saving, a bad suggestion shows as "AI: this text looks misread" with **⚑ Flag for review** (`aiFlag`) instead of Accept, and Accept-all flags such cards.
- **Request:** OpenAI-style `POST {base}/chat/completions` with `Authorization: Bearer` (system + user message, temperature 0), or `api.anthropic.com/v1/messages` for Claude (`anthropic-dangerous-direct-browser-access`). Payload per card: hanzi, pinyin, meaning, note, why (flagged / uncertain reading / pending), gloss, alt (the other readings, v96) — **never photos**. Reply = JSON array `[{c,zh,zht,p,m,note,ok,bad}]` (`zht` only for `script:"traditional"`). Cost ≈ 400 input + 100 output tokens per card, well under ¥0.01 at DeepSeek; a hundred cards a day ≈ ¥0.10–0.20.
- **Where it acts:** in the Read preview before saving (result shown in green, Save stores it verified); after saving as a suggestion stored `ai:{zh,p,m,note,ok,at,model}` with **Accept** (applies pinyin/meaning, fixes the text in place via `applyCardUpdate`, clears flag and `suspect`, `mt.src:"llm",verified:true`) or **Dismiss** — on the study back, in the card detail, under the photo, and via the **"N AI suggestions waiting — Accept all"** bar on the Cards tab; in the **Edit form** ("Ask AI to check text, pinyin and meaning" fills the fields in place, stored on Save). **Ask AI about N cards** in More sends the whole queue (`aiQueue()` = flagged + uncertain + pending) in one request; the auto run (`aiAuto`, `aiAutoSoon` 1.5 s after a save, and on `online`) does the same for pending/uncertain cards.

## Hard constraints (learned in the field — do not violate)
1. **No external dependencies / CDNs.** Must run offline and behind the GFW. System CJK fonts only. Libraries and data go into `vendor/` (licenses in `vendor/LICENSES.txt`).
2. **All paths relative** (`./…`). The app lives under a subpath (`/zeichentrainer/`).
3. **Persistence only via IndexedDB** (do not use localStorage/sessionStorage). `navigator.storage.persist()` is requested — Xiaomi/MIUI aggressively evicts storage of non-installed sites. The SW must **never cache non-OK responses** — a 404 cached during a deploy window poisoned the dictionary permanently once; `loadDict` additionally heals such entries.
4. **Phone-only deploys:** H uses GitHub only in the phone browser. Ship changes as small, clearly described PRs. As few files as possible; generate/commit binaries (icons, vendor data) in the repo, never ask H to upload them.
5. **Privacy rule:** Confidential text (real contracts, suppliers, company internals) must **never** end up in the public deck or repo. General vocabulary only. Photos and card images stay on the device.
6. **Files leave the device only via the share sheet:** programmatic blob downloads (`<a download>`) are silently blocked by Android/MIUI. Use `navigator.share` with a file — and Chrome/Android only shares whitelisted types (`.txt`/`.csv`/images/PDF yes, **`.json` no**), hence the `.json.txt` extension with `text/plain`.

## Deck format
No built-in deck; all cards live in IndexedDB `custom`. Schema:
```
{ id:"坚果", c:"坚果", p:"jiānguǒ", m:"nuts", t:"Custom", at:1756800000000,   // id: the key (text while free, else 坚果#<at>) · t: Custom | Sign · at: creation time
  seg:["坚果","\n","供应"],           // optional: word boundaries + photo line breaks for the front
  lb:"photo"|"auto",                    // where the line breaks came from (auto = estimated from the crop's shape)
  w:"…", wp:"…", wm:"…",              // optional: context word + pinyin + meaning
  shot:"shot_1756800000000",           // inbox photo the card came from (photo cleanup)
  mt:{ src:"llm"|"dict"|"phrasebook"|"nmt"|"gloss", verified:true|false, pending:false, suspect:"reason" },
  flag:true, flagNote:"…",            // review flag
  alts:["养兴多","义乐多"],               // optional: the other readings of the photo (v96), for the AI check
  trad:"養樂多",                          // optional: the text as it stands on the photo, in traditional characters (v101); shown on the front, c stays simplified
  ai:{ zh, p, m, note, ok, bad, at, model } // a waiting AI suggestion (bad: the AI calls the text OCR garbage)
}
```
Sign cards add `kind:"sign"`, `segs` (per line) and `gloss` (`[{w,p,m}]`, feeds the parts row); word cards from the Read path carry `gloss` too; any card saved from a photo carries `img` (crop) and `imgFull` (whole photo: list thumbnail and the front toggle — not repeated on the back, H) — blobs, local only, never exported.
Rules: **Pinyin only verified, with correct tones — never guess.** Meanings in English. Dictionary/phrasebook prefills are `verified:false` until a human or the AI checked them; when unsure, flag instead of inventing.

## Testing
No test files in the repo. A full audit (dead code, unused CSS, duplicated helpers, stale comments) was done at v81; the mechanical scan for unreferenced functions, constants and CSS classes, and the check that every identifier named here exists in the code, are worth repeating after larger changes. Left as they are on purpose: the AI request transport exists twice (`aiAsk` with the richer error mapping, `aiCharAlternatives` without) and the share-sheet dance twice (`shareFlagged`, `exportData` with different fallbacks) — merging them would change error texts. The old offline-translation test (`verify-nmt`) fails on "model present but off" since an earlier version — the app's translate and pending paths still pass inside it; the fake-model seed no longer matches how the cache is checked. Each session verifies in headless Chromium (Playwright with the pre-installed browser, a local static server under `/zeichentrainer/`, the OCR/dictionary/pinyin files from `vendor/`, AI endpoints mocked with `page.route`): a seed script fills IndexedDB before the app loads, then scripts drive the UI and check state (`S`, `SIGN`, `DICT` are globals). Scripts live in the session scratchpad and are gone afterwards — rebuild them when needed; the header check `PWA vN` has to follow every bump. The set at v117: the flow (photo → crop → read → flag → save, plus an Edit form left by a tab tap), the two-pass reader on ten images (a decorated composite, a 12° sign, 业主直租 in two polarities, a digits line, a two-line sign, and four regions cut from H's screenshots at the frame's coordinates — the Yakult logo twice, the granite sign and the escalator sign; the door plate 推 is read on its own; the cuts were made with PIL from the uploaded screenshots, 14 px inside the frame, and are gone with the scratchpad), the picker, the picker's add and remove (+ before / + after, no + tile, the red Remove, the Edit form's links) and the preview's line input (typing 拉 redraws the strip), the drawing sheet, the Edit form, the card detail and list, the AI review with a mocked endpoint (a good answer, a "bad" answer, a Chinese-only meaning, a traditional `zh`), two readings of the same photo started 400 ms apart (one result, one AI request), the dictionary consensus with the phone's own candidate list, the traditional form end to end, the same text saved from two photos with the v2→v3 migration and an old export, the linked cards (the row on the back and in the detail, the tap, the list pill), Diagnostics, the mirror, the vendor fallback and the shell self-repair; two of them (mirror, shell) only pass when not run under heavy parallel load.
