# CLAUDE.md — 识字 Zeichentrainer

Working language: **English.** Reply to H in English. Short, direct, no excessive politeness.

## What this is
Chinese character trainer for adults (spaced repetition), a reinterpretation of 悟空识字 without the kids' aesthetic.
User: H, product manager, Beijing, **phone-only (Android/Xiaomi, Chrome, VPN), no computer**.
UI language: English. Learning content: Chinese + pinyin + English meaning.

## Live deployment
- Repo: `henglicam/zeichentrainer` · GitHub Pages, branch `main`, folder `/ (root)`.
- URL: `https://henglicam.github.io/zeichentrainer/`
- Push to `main` → Pages rebuilds automatically (~1–2 min). `index.html` must stay in the repo root.
- The site is **public** (free plan). User data lives exclusively on the device (IndexedDB), never in the repo.

The app updates itself (update check on load/foreground, auto-reload on `controllerchange`); the vendor cache `zt-ocr-v1` survives shell updates — bump it only when vendor files change.
- **No VPN needed to use the app (H's requirement):** the installed app runs from its cache, DeepSeek is reachable from China, and updates also arrive through a **mirror** — More → Updates without a VPN (setting `mirror`, default jsDelivr `cdn.jsdelivr.net/gh/henglicam/zeichentrainer@main/`, **field-verified reachable from H's phone without VPN**). The page posts `mirror-update` (with its own version label) to the worker on start/foreground (at most hourly) or on "Check now"; the worker reads `PWA vN` from the mirror's index.html and, if newer, fetches the shell assets into the current cache — content types by extension, because jsDelivr hands HTML out as text/plain — and the page reloads (`mirrorUpdate` in `sw.js`, `mirrorCheck` in `app.js`). The worker script itself only ever comes from github.io (it just carries the cache name). Still VPN-only: a first install if github.io is blocked, the 50 MB model download (jsDelivr caps files at 20 MB), the Claude provider.
- **Persistence:** IndexedDB `zeichentrainer` v2 — `progress` (keyPath `c`), `custom` (keyPath `c`, all cards), `inbox` (keyPath `id`, photos), `settings` (keyPath `k`). No built-in deck; `deck()` is `S.custom`, sorted by creation time `at` (oldest first, so cards are learned in the order they were taken; the Cards list shows newest first). At boot, progress rows without a card are pruned.
- **Tabs:** Learn · Cards · Camera · More. A tab tap always leaves the edit form; tapping **Cards** while a card is open returns to the list.

### The flow (AI-first — "nobody wants to see OCR if not necessary")
1. **Camera:** `<input type="file" capture="environment">` (Take photo) or `<input type="file" multiple>` (**From album** — several at once, all land in the inbox, the first opens in crop mode; `addPhoto` per file) → the photo is normalized (EXIF baked in, max 1600 px) and stored in `inbox`. A pulsing "Processing photo …" placeholder appears at once; the inbox re-renders on `visibilitychange`; pull-to-refresh is off (`overscroll-behavior-y: contain`).
2. **Frame:** the photo lands directly in crop mode (bright dashed frame with a dark outline, nothing dimmed, corner handles resize, dragging inside moves, preview below). **Reading starts by itself 1.2 s after the finger lifts** (`READ_TIMER`; a corner drag restarts the wait; "Read now" and a small "Image only" link remain). No dialogs in the flow: no frame → nothing happens, a duplicate text is an inline note. **The frame stays on the photo** through reading and the card preview (`cropRectStyle` re-draws it from `CROP.rect` in percentages after any re-render) and goes only on Save, Cancel or Split into words; a corner drag meanwhile re-reads.
3. **Read** (`cropSign`): on-device OCR line by line — the status text lives in `READING[id]` and is re-queried on every update, so a re-render (foreground return, AI answer for another photo) cannot swallow it or the error — (Tesseract.js 7, `chi_sim`, PSM 6, symbols under confidence 35 dropped) → editable text (tap to correct) → **automatic AI check** (`signAskAI`, when the AI is live) → the preview shows "Read and checked by the AI" with pinyin, meaning and the AI's note → **Save card**. One line of ≤ 4 characters becomes a word card (`t:"Custom"`, `seg`, crop image), anything longer a sign card (`kind:"sign"`, lines joined with `\n`, `segs`, `gloss`, `img` + `imgFull`). Cards checked here are stored `mt:{src:"llm",verified:true}`.
4. **Meaning priority** (H's rule): online AI → phrasebook → offline model → word gloss. `aiLive()` = key set + auto on + `navigator.onLine`. While the AI is live the offline model is not run and Save waits for the running AI check (`sg.aiPromise`); if the call fails, `sg.aiErr` is set and the offline model takes over; with neither, the card gets the gloss and `mt.pending:true` and is completed by the post-save auto run when online.
5. **Split into words** (secondary): drops back to the overlay path (`onOcr` with the remembered `region`): pinyin boxes over the characters (hidden while the AI is live unless `SHOWBOX[id]`; "Pick words on the photo" brings them back), lines segmented into CC-CEDICT words (`segmentChars`, greedy longest match), tap selects a whole word, selection bar with a **phrase row** (whole string = one card, `seg` keeps word boundaries and a `"\n"` token where the photo breaks the line) and one row per word, each with Save / Edit… / **Ask AI** ("Ask again" once checked; every selection is checked automatically, debounced 1.2 s, cached in `AIFIX[id][text]`). Word cards from here: `mt:{src:"dict",verified:false}` plus `mt.suspect:"<reason>"` when the reading is uncertain (`ocrDoubt`: mean symbol confidence < 70 %, unknown words, no meaning) or `src:"llm",verified:true` after the AI check.
6. **After saving:** the note under the photo says what was saved and where the meaning came from, with a **Next photo** button that opens the camera straight away. Photos picked from the album that are still waiting keep their CROP button below. `QSCARD[id]` remembers the card; if the AI answers later, the jade suggestion box with **Accept / Dismiss** appears right there.

### Online AI review (T3, opt-in, text only)
- **Setup:** More → Online AI review → **provider** (`AI_PROVIDERS`: DeepSeek default — **field-verified from the phone, no VPN** —, Qwen/Alibaba Bailian, GLM/Zhipu, Claude, custom OpenAI-style base URL; the Chinese ones take WeChat Pay/Alipay, H could not buy Anthropic credit from China), API key (settings store, device only, never exported), model (defaults `deepseek-chat`, `qwen-plus`, `glm-4-flash`, `claude-sonnet-5`), checkbox "Check every new card with the AI automatically" (default on). Settings: `aiProvider`, `aiBase`, `aiKey`, `aiModel`, `aiAuto`.
- **Request:** OpenAI-style `POST {base}/chat/completions` with `Authorization: Bearer` (system + user message, temperature 0), or `api.anthropic.com/v1/messages` for Claude (`anthropic-dangerous-direct-browser-access`). Payload per card: hanzi, pinyin, meaning, note, why (flagged / uncertain reading / pending), gloss — **never photos**. Reply = JSON array `[{c,zh,p,m,note,ok}]`. Cost ≈ 400 input + 100 output tokens per card, well under ¥0.01 at DeepSeek; a hundred cards a day ≈ ¥0.10–0.20.
- **Where it acts:** in the Read preview and the selection bar before saving (result shown in jade, Save stores it verified); after saving as a suggestion stored `ai:{zh,p,m,note,ok,at,model}` with **Accept** (applies pinyin/meaning, renames the card if the text was fixed via `applyCardUpdate`, clears flag and `suspect`, `mt.src:"llm",verified:true`) or **Dismiss** — on the study back, in the card detail, under the photo, and via the **"N AI suggestions waiting — Accept all"** bar on the Cards tab; in the **Edit form** ("Ask AI to check text, pinyin and meaning" fills the fields in place, stored on Save). **Ask AI about N cards** in More sends the whole queue (`aiQueue()` = flagged + uncertain + pending) in one request; the auto run (`aiAuto`, `aiAutoSoon` 1.5 s after a save, and on `online`) does the same for pending/uncertain cards.

### Offline translation (T2, opt-in)
Firefox Translations `zh-Hans→en` v2.0a2 (Mozilla, MPL-2.0; model 44 MB + shortlist 4.7 MB + vocab 0.7 MB gzipped = 50 MB) in the Bergamot WASM engine (`vendor/nmt/translator-worker.js` + `bergamot-translator-worker.{js,wasm}`, npm `@browsermt/bergamot-translator` 0.4.9, no SharedArrayBuffer). Fetched by the **GitHub Action "Fetch zh→en translation model"** (workflow_dispatch) from **Mozilla Remote Settings** (the source Firefox uses; the Git LFS objects on GitHub are gone, 410; the build sandbox cannot reach Mozilla) — it writes `nmt-model.json` (sizes, sha256), bumps both version markers and pushes branch `nmt-model`; Actions may not open PRs here, so the PR is opened by hand. Enable under More → Translation (size prompt; files cached in `zt-ocr-v1`), setting `nmt`; used **only without a connection** once the AI is set up. `signMeaning(lines)` → `{m, src: phrasebook|nmt|gloss, pending}`; "Translate pending" in More completes gloss-only cards. Verified on the build machine (~40 ms per sentence after load), **not yet timed on the Xiaomi** — the More row shows "loaded in N s, last translation N s" (`NMT.loadMs`, `NMT.lastMs`) for that field test.

### Learning and the library
- **Learn:** SM-2 light; progress rows are `{c, interval, ease, due, reps, fails, last}` (`last` = day of the last review); every review day is appended to setting `days` (max 400) for the **streak**; `learnStats()` → cards learned / reviewed this week / streak, shown on the All-clear screen and in More → Progress — `fails` counts consecutive "again" (hard keeps it, good/easy reset it) and at `LEECH_FAILS` = 4 the card is **flagged automatically** ("failed N times in a row — check text, meaning and photo"): a leech is usually a bad card, not a bad memory. Front = photo (crop) above the text box (see **Line breaks** and Design). No tag row, no Reveal button — **tapping the character toggles the back on and off; tapping the photo swaps the crop for the whole photo and back** (`S.fullPic`, `frontPic`, reset on the next card). Back = pinyin with a **speaker button** (the phone's own zh-CN voice via `speechSynthesis`, nothing downloaded, shown only when such a voice exists — `ttsVoice()`, voices arrive asynchronously on Android), meaning, a **parts row** — the card's dictionary words as buttons (from `gloss`/`segs`/`seg`; a single-word card shows its characters instead), tap one for pinyin and meaning, a multi-character word then offers its characters as a sub-row (`cardParts`/`charsHTML`/`charInfo`, dictionary loaded on first tap, offline; CC-CEDICT clutter like `[Tian1 jin1 shi4]` and `CL:` stripped by `cleanSense`). No word or gloss tables on the back (H: redundant) —, (context word), the **whole photo** as context at the bottom (`imgFull`, stored for every card saved from a photo; older cards fall back to the inbox photo via `shot`), then **Again / Hard / Good / Easy** with interval preview (after grading the next card appears at the top of the screen), and underneath **⚑ Flag for review** and **✎ Edit** (`S.editFrom="study"`, Back/Save return to the revealed card). No example sentences (H's decision). Empty deck → "No cards yet" + Take a photo.
- **Line breaks — the card text follows the photo, automatically (H's rule):** the front never wraps on its own; up to 3 characters sit in the square reticle, longer words get a wide box and the font is fitted to the longest line (`frontLines`, `frontBox`). Where the lines come from: the reader keeps Tesseract's lines (sign cards: `c` with `\n`; word cards: a `"\n"` token in `seg`, chars carry `ln`); the AI's answer is re-cut to those lines when the model drops the `\n` (`recutLines`: old break offsets, so a corrected character keeps them and an added one only lengthens the last line); a rename keeps them the same way (`segWithBreaks`); the Edit form shows word cards as a textarea with one line per photo line. Cards without any line data (before v39) get their lines **estimated once at boot** from the crop's shape (`autoBreaks`: L ≈ √(n·h/w), cut at word boundaries, stored with `lb:"auto"`); cards with real line data are `lb:"photo"` and never touched.
- **Cards:** every card newest first with a 104×58 thumbnail of the **whole photo** (`imgFull`, fallback inbox photo, else the crop; `object-fit: contain`) or a glyph tile, pinyin, meaning, ⚑ review / jade AI pill and the real SRS status (`due`, `in N d`); search over hanzi, pinyin, meanings, context words and flag notes; chips **⚑ Review (N)** (flagged + suggested) and **Unverified (N)**; **+ New** opens the Add form. Detail: front + back preview, SRS stats, **Test this card** (studies that card and then continues down the list, newest first; ← Cards stops and restores the session queue), **Edit** (pinyin, meaning, context word, example, image removal, **and the Chinese text itself** — progress, images, queue entries move to the new key via `applyCardUpdate`; pinyin/segmentation/gloss recomputed unless pinyin was edited by hand; editing marks `verified`, clears `pending` and `suspect`), **⚑ Flag / Clear flag**, **Delete**.
- **Review flag:** `flag:true` / `flagNote` on the card; included in export. More → **Flagged cards → Share** sends a plain-text list via the share sheet (`.txt`) for a teacher.
- **Export/import** (More): progress + cards as JSON, `zeichentrainer-YYYY-MM-DD.json.txt` via the share sheet; import validates by content and upserts, keeping local images. The Export row shows **"Last export: N days ago"** (setting `lastExport`), red after 30 days or when never exported — the cards exist only on this phone. **Photos** row: inbox count, and a **Delete N** button for photos older than 30 days that already became a card (cards carry `shot:<inbox id>`; the cards keep their own crop). **Reset** wipes cards, progress and photos.

## Hard constraints (learned in the field — do not violate)
1. **No external dependencies / CDNs.** Must run offline and behind the GFW. System CJK fonts only. Libraries and data go into `vendor/` (licenses in `vendor/LICENSES.txt`).
2. **All paths relative** (`./…`). The app lives under a subpath (`/zeichentrainer/`).
3. **Persistence only via IndexedDB** (do not use localStorage/sessionStorage). `navigator.storage.persist()` is requested — Xiaomi/MIUI aggressively evicts storage of non-installed sites. The SW must **never cache non-OK responses** — a 404 cached during a deploy window poisoned the dictionary permanently once; `loadDict` additionally heals such entries.
4. **Phone-only deploys:** H uses GitHub only in the phone browser. Ship changes as small, clearly described PRs. As few files as possible; generate/commit binaries (icons, vendor data) in the repo, never ask H to upload them.
5. **Privacy rule:** Confidential text (real contracts, suppliers, company internals) must **never** end up in the public deck or repo. General vocabulary only. Photos and card images stay on the device.
6. **Files leave the device only via the share sheet:** programmatic blob downloads (`<a download>`) are silently blocked by Android/MIUI. Use `navigator.share` with a file — and Chrome/Android only shares whitelisted types (`.txt`/`.csv`/images/PDF yes, **`.json` no**), hence the `.json.txt` extension with `text/plain`.

## Design (material language frozen; mobile treatment updated 2026-09-02 on H's request)
Material language: 漆器 (lacquerware) + seal red. Deliberately not the default AI look.
- Colors: INK `#141410` · PANEL `#1C1C16` · PANEL2 `#232319` · BONE `#EDE6D6` · MUTE `#8C8677` · FAINT `#57544A` · VERM `#B23A2E` · JADE `#7C9A86` · LINE `#2E2E24`
- Fonts: Hanzi = `'Songti SC','STSong','Noto Serif CJK SC','Source Han Serif SC','SimSun',serif` · body = system sans · labels/data = mono
- Signature element: the character sits in a **田字格 reticle** (260px square up to 3 characters, LINE border, 14px BONE corner ticks, dashed VERM crosshair **only for single characters**). Longer words get a **wide box** (viewport − 32 px, max 440) and the font shrinks so the longest photo line fits on ONE line — the text never wraps except where the photo does (`frontLines`/`frontBox`, v42, H: "the image is one line"). Base font by character count: 1→150px, 2→104, 3→74, 4–8→58, 9–12→44, 13+→34. Sign fronts use the same fit rule.
- **Readability (v25):** body 17px; labels/hints/list heads are sans 13px medium in `--text2 #B9B19E` (mono is reserved for pinyin and numbers, no more uppercase-mono captions); meanings on the card back 18px BONE; tab labels 12px sans; pills/chips rounded sans; all UI copy uses plain words and parentheses instead of `·` shorthand. Top bar shows Due/Done on Learn and Deck on the other tabs (three pills overflow at 390px).
- **Mobile treatment (v22):** sticky, blurred top bar (logo + `PWA vN` + stat pills, DUE/DONE only on Learn) · **bottom tab bar** in thumb reach with line icons (active icon in VERM) · radius 12px on cards/buttons/inputs, 10px on images · touch targets ≥ 44px (mini buttons 44, grades 58, round `ocr-btn` pills 38) · one-line hints instead of paragraphs · inputs 16px to avoid zoom · safe-area padding top/bottom · `-webkit-tap-highlight-color: transparent`, visible `:focus-visible` in JADE.
- The crop frame must stay visible on any photo color: bright dashed edge with a dark outline (red-on-red lesson); nothing is dimmed, inside or outside.

## Didactics / SRS
- Loop: photo + character/word → tap to reveal → pinyin (+ pronunciation), meaning, (context word). No example sentences (H's decision).
- SM-2 light, grades `again / hard / good / easy` with interval preview. `again` re-queues the card within the same session.
- Session = due cards + max. 8 new ones. "Pull forward" pulls future cards when nothing is due.

## Deck format
No built-in deck; all cards live in IndexedDB `custom`. Schema:
```
{ c:"坚果", p:"jiānguǒ", m:"nuts", t:"Custom", at:1756800000000,   // t: Custom | Sign · at: creation time
  seg:["坚果","\n","供应"],           // optional: word boundaries + photo line breaks for the front
  lb:"photo"|"auto",                    // where the line breaks came from (auto = estimated from the crop's shape)
  w:"…", wp:"…", wm:"…",              // optional: context word + pinyin + meaning
  shot:"shot_1756800000000",           // inbox photo the card came from (photo cleanup)
  mt:{ src:"llm"|"dict"|"phrasebook"|"nmt"|"gloss", verified:true|false, pending:false, suspect:"reason" },
  flag:true, flagNote:"…",            // review flag
  ai:{ zh, p, m, note, ok, at, model } // a waiting AI suggestion
}
```
Sign cards add `kind:"sign"`, `segs` (per line) and `gloss` (`[{w,p,m}]`, feeds the parts row); word cards from the Read/overlay path carry `gloss` too; any card saved from a photo carries `img` (crop) and `imgFull` (whole photo: context on the back, list thumbnail, front toggle) — blobs, local only, never exported.
Rules: **Pinyin only verified, with correct tones — never guess.** Meanings in English. Dictionary/phrasebook prefills are `verified:false` until a human or the AI checked them; when unsure, flag instead of inventing.
New words come from photos (menus, signs, packaging).
